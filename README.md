# SignalMesh — Real-Time Communication Platform

### Live Project

```text
https://signal-mesh.onrender.com/
```

SignalMesh is a FastAPI-based real-time chat platform that combines HTTP endpoints, JWT-authenticated WebSocket sessions, SQLite persistence, and optional AI/embedding-backed reply suggestions.

## What It Does

- Real-time broadcast chat over WebSockets with anonymous and authenticated clients.
- JWT login flow with password hashing through `passlib` and `argon2`.
- Persistent message storage via SQLAlchemy models backed by SQLite or `DATABASE_URL`.
- File uploads, presence updates, typing indicators, and message fan-out through the WebSocket layer.
- Optional semantic reply suggestions using `sentence-transformers` and `groq` when configured.

## Stack

- `FastAPI`
- `WebSockets`
- `SQLAlchemy`
- `SQLite`
- `JWT` via `python-jose`
- `passlib[argon2]`
- `Render`
- Optional: `sentence-transformers`, `groq`

## Runtime Layout

- `server.py`: main FastAPI application, routes, WebSocket handlers, auth, persistence, and suggestion logic.
- `database.py`: SQLAlchemy engine, session factory, and `User` / `Message` models.
- `run.py`: safe startup wrapper that imports `server.py` first and then launches Uvicorn on `PORT`.
- `static/`: browser client (`chat.html`, `chat.js`, `style.css`).
- `benchmarks/`: reproducible k6 scripts plus captured JSONL outputs.

## Environment Variables

The app reads the following runtime variables:

- `SECRET_KEY`
- `DATABASE_URL`
- `PORT`
- `GROQ_API_KEY`
- `MAX_RECENT`
- `TOP_K`
- `AI_CONTEXT_LINES`
- `MAX_SUGGESTION_WORDS`
- `EMBED_MODEL`
- `MODEL_CACHE_FOLDER`

If `DATABASE_URL` is not set, the app falls back to local SQLite at `sqlite:///./world_chat.db`.

## Run Locally

```powershell
python -m pip install -r requirements.txt
uvicorn server:app --reload
```

If you want the same startup path used by Render, run:

```powershell
python run.py
```

## Deployment Notes

- `run.py` is the safest production entry point because it surfaces import-time errors before Uvicorn starts.
- Render should provide `PORT` and `DATABASE_URL`.
- SQLite works for local testing, but production should use the configured database URL.

## Benchmarks

The benchmark artifacts are stored in `benchmarks/` as JSONL streams generated by k6. The tables below summarize the observed points directly from those files.

### How To Re-run

```powershell
k6 run .\benchmarks\http_load.js
k6 run .\benchmarks\http_stress.js
k6 run .\benchmarks\ws_load.js
k6 run .\benchmarks\ws_stress.js
```

The k6 scripts use these scenario settings:

- `http_load.js`: `ping_latency` and `login_throughput` at 1 VU each.
- `http_stress.js`: ramping HTTP `ping` load up to `CONNECTED_USERS`.
- `ws_load.js`: authenticated WebSocket chat session with message send/receive tracking.
- `ws_stress.js`: ramping WebSocket connection stress against `/ws`.

## Interpretation

- `http_load.json` shows normal request latency in the low hundreds of milliseconds, with one accepted setup rejection and a successful authenticated login bootstrap.
- `http_stress.json` demonstrates the service sustaining 100 concurrent VUs without request failures, but with latency widening into multi-second territory.
- `ws_load.json` confirms authenticated WebSocket behavior with sub-400 ms message round trips.
- `ws_stress.json` shows connection establishment pressure at scale, but no connection-check failures in the captured data.
